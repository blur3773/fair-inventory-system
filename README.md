# Система учёта товаров на ярмарке

Консольное приложение для учёта товаров, продавцов, продаж, остатков и выручки на ярмарке. На ПР3 проект переведён с функциональной модели ПР2 на объектную модель.

## Возможности

- просмотр товаров, продавцов и журнала продаж;
- поиск товара по части названия;
- проверка наличия товара;
- добавление продавца и товарной позиции;
- регистрация и отмена продажи;
- сортировка и отбор товаров по остаткам;
- расчёт статистики по активным продажам;
- сохранение данных между запусками в JSON-файлах.

## Объектная модель

### Seller

Продавец ярмарки. Атрибуты: `id`, `name`, `contact`. Методы: `from_data()` для загрузки из JSON, `to_data()` для сохранения и `__str__()` для вывода.

### Product

Товар продавца на стенде. Атрибуты: `id`, `name`, `seller`, `stand`, `total_quantity`, `unit_price`. Методы: `get_remaining_quantity()`, `is_available()`, `calculate_revenue()`, `get_stock_status()`, `from_data()`, `to_data()` и `__str__()`.

### Sale

Продажа товара. Атрибуты: `id`, `product`, `quantity`, `sale_date`, `revenue`, `is_cancelled`. Объект `Sale` хранит ссылку на объект `Product`, а доступ к продавцу возможен через `sale.product.seller`. Методы: `cancel()`, `from_data()`, `to_data()` и `__str__()`.

Отмена продажи не удаляет объект из журнала: метод `cancel()` устанавливает `is_cancelled = True`. Отменённая продажа не уменьшает остаток и не входит в статистику.

## Структура проекта

- `main.py` — точка запуска, меню и пользовательские сценарии;
- `models/` — классы `Seller`, `Product`, `Sale`;
- `inventory.py` — функции работы с коллекциями объектов;
- `storage.py` — преобразование JSON в объекты и обратно;
- `utils.py` — безопасный ввод чисел и дат;
- `data/sellers.json` — данные продавцов;
- `data/products.json` — данные товаров с `seller_id`;
- `data/sales.json` — журнал продаж с `product_id` и статусом отмены;
- `tests/` — автоматические тесты классов и операций;
- `requirements.txt` — зависимости разработки.

## Хранение данных

JSON-файлы содержат обычные данные, а не внутреннюю структуру Python-объектов. При запуске `storage.py` создаёт объекты `Seller`, затем `Product`, затем `Sale` и восстанавливает связи между ними. При сохранении ссылки на объекты преобразуются в идентификаторы `seller_id` и `product_id`.

Начальный сценарий ПР1 сохранён: для мёда с исходным количеством 50 единиц есть активная продажа 18 единиц. Остаток равен 32 единицам, выручка — 8100 руб.

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```
